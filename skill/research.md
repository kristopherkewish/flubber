# Research phase

Run this every suggest run, before drafting ideas. Use WebSearch (load it with ToolSearch `select:WebSearch` if it is deferred). Use `standard` mode by default; use `extended` only when results are thin, off-target or possibly outdated. Send independent searches in one turn.

## Budget
Roughly 4-8 searches per run. Check `research-notes.md` first and skip topics researched in the last 30 days.

## What to look up
1. **Trends:** what is currently trending in the target gap areas (new languages, frameworks, agent/workflow patterns, MCP, local models, tooling, embedded, scientific computing...). Prefer sources from the last 6-12 months.
2. **Prior art:** existing projects, repos, courses and "awesome" lists for each candidate direction. Note what already exists so the idea can differ or build on it.
3. **Interest intersections:** projects at the crossing of a gap area and one of the user's interests (e.g. hardware + music, science + software, games + algorithms).
4. **Verification of every tool you plan to recommend:** is it still maintained (recent releases/commits), is it free at the user's budget (no paid API required unless flagged), and does it work on Windows or have a sensible alternative? Say plainly when you could not verify.

## Output rules
- Attach source links to each idea in the presentation.
- Label claims: **verified** (seen in a source), **opinion/memory** (yours), or **unverified**.
- Vendor blogs and single-author posts are signals, not proof; do not present them as fact.
- Do not invent URLs or version numbers.

## Caching
Append to `D:\flubber\state\research-notes.md` a dated entry: topic, key findings, URLs. Remove entries older than 90 days when you touch the file.
